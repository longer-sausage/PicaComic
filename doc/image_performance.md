# 图片加载与 WebP 动图性能

图片展示组件共用 `ImageDisplay`：首帧、尺寸变化、加载进度和错误才更新组件状态；
其余动画帧通过 `ValueNotifier` 直接更新 `RenderImage`，由独立的重绘边界隔离。
封面、连续阅读、双页阅读、单页缩放阅读和图片查看页均接入这条绘制路径。
单页阅读使用 `PhotoView.customChild` 保留缩放手势，避免依赖内的图片包装组件逐帧重建。

## 解码与内存

- 缩略图根据实际布局和屏幕像素密度选择解码尺寸，以 64 物理像素为步长复用缓存。
  `width/height: double.infinity` 会使用布局约束中的有限尺寸。
- 阅读器静态图片恢复原有的 `FilterQuality.medium` 缩放采样，图片查看页也使用相同质量；两者保留原始分辨率，
  避免为播放性能降低静态漫画细线和文字的采样质量；静态图片缩放不触发额外解码。
- 单页、连续和双页阅读的动图共用缩放分辨率更新逻辑，在缩放稳定 250 ms 后更新目标分辨率，
  目标不超过原始分辨率，保留旧帧直到新分辨率可用。相同倍率下的平移不会推迟更新。
  切换图片或控制器时取消过期更新，释放相关监听；两页分别按各自的显示区域计算像素尺寸。
  250 ms 是发起更新前的防抖等待，高清帧仍需解码；切换分辨率会重建该动图缓存，播放可能从头开始。
- 循环动图只在预算允许时缓存完整一轮。总预算 64 MiB，单张上限 24 MiB；
  超出预算时继续逐帧解码。缓存保留每帧时长和透明度。
- 对忽略动图目标尺寸的 Flutter 引擎，首次解码后缩小完整合成帧，再复用缩小后的 GPU 图像。
  首轮有缩放和缓存开销，后续循环省去重复解码与纹理创建。
- 图片离开滚动视口、路由停止活动或应用进入后台时移除播放监听；暂停的图片释放整轮帧缓存，
  保留当前画面，并在未完成的帧解码结束后释放原生解码器及其合成缓冲区，返回时从原始数据缓存恢复。
  系统内存压力也会释放帧缓存。
- 原始图片数据采用有严格字节上限的 LRU 缓存。同一图片的不同显示尺寸、前台加载和预加载共享
  正在进行的请求；过大的单张图片不会挤走整个缓存。

## 加载

章节加载先绘制第一帧的加载提示，再执行图源代码；同一章节的重复构建共享一次请求，
切换章节、重试或退出后，旧请求的结果不会覆盖当前页面。

阅读器在章节地址就绪后优先获取当前页原始数据，连续阅读按真正进入视口的页面安排优先级，
双页阅读同时优先获取本屏两张图片。单页、双页模式在当前页数据就绪后，后台最多并行预加载两项；
连续模式持续使用六个加载槽位，任何慢图均不会阻塞其他图片的启动和补位。
连续模式至少准备后续六页，并随屏内页数扩大准备范围；更大的预加载设置仍生效，设置为零则关闭预加载。
跳页时调度器另外保留两个可见页槽位，替换尚未启动的旧任务。
翻页或跳转会替换尚未启动的任务，切换章节和退出阅读器会清空队列。
进入和退出阅读器只调整原始数据缓存预算，不再清空已经缓存的图片和共享的在途请求。

连续阅读在视口前后一屏范围内提前准备首帧，已准备好的静态图片进入视口时可直接显示；
屏外动图准备首帧后暂停，进入视口时恢复播放，不会在屏外持续解码整轮动画。
连续模式的图片在快速滚动期间也会准备首帧，不再等待滚动减速；屏外下载进度只更新数据，不触发组件重建。
其他阅读布局仍在图片可见时启动解码。
可见性还会在图层合成后检查，覆盖前一张图片尺寸变化、缩放和平移造成的位置变化；
检查会合并到每帧一次，不在静止时持续生成新帧。

加入共享请求的组件会立即收到最新进度，之后同步接收节流后的更新。
尚无数据、零进度、未知总长度和等待解码时均显示转动的加载环，收到部分数据时显示下载进度。
临时传输错误的重试间隔为 250、750、1500 ms；遇到损坏的缓存或非图片响应时，清理缓存并重新获取一次，
仍然失败则保留错误提示和手动重试入口。

多条图片下载路径和文件写入缓冲改用 `BytesBuilder`，避免按 `List<int>` 存储每个字节的额外开销。
没有同图片任务时，移除了原先固定的 300 ms 等待；下载进度通知最多每 50 ms 一次，完成通知保留。
